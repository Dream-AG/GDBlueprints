# GDBlueprints

Build Godot gameplay with visual graphs that generate ordinary GDScript. This alpha provides Events, Flow, Actions, and typed Values for 2D, 3D, and UI. Familiar Unreal names are paired with Godot behavior; they do not promise identical Unreal semantics.

## Start in five steps

1. Install the addon in `addons/GDBlueprints/` and enable **GDBlueprints** in Project Settings → Plugins.
2. Create a scene with a Node3D, Node2D, or Control. Attach a saved GDScript. A child node can own its own graph too.
3. Select that node and open the **GDBlueprints** bottom panel. Right-click the graph and search for **Event BeginPlay** and **Print String**.
4. Connect BeginPlay's execution output to Print String. Enter a message, then press **Compile Blueprint → GDScript**. Save the scene and script.
5. Run the scene. The message appears in Godot's Output panel. In this compiler, BeginPlay runs on the first process pass after `_ready()`.

If your attached script already defines `_ready`, `_process`, or another callback generated by the graph, move your handwritten behavior into a named helper and call it with **Call Object Method**. Compilation reports conflicting names before writing.

## Current scope

The registry contains 172 built-in definitions, including UI wrappers and compatibility nodes. This is not full Unreal Blueprint parity. Use Object property/method nodes and handwritten helper scripts when a dedicated operation is missing. Check the node reference before assuming a familiar Unreal label behaves identically.

Try the [playable 2D and 3D examples](gameplay-examples.html) to explore movement, collision, spawning, pickup collection, signals, health and HUD logic in editable graphs.

See [Persistence and reusable graphs](persistence-and-reuse.html) for typed checkpoint saves, version migrations, backup recovery, reusable scenes/functions, and graph templates.
